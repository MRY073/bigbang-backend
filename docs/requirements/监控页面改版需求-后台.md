# 监控页面改版需求文档（后台开发）

## 一、需求概述

对三个监控页面（成品链接监控、潜力链接监控、自然流商品监控）进行改版，主要变更如下：
1. 隐藏原有的日均指标和波动指标
2. 新增折线图数据接口，返回时间序列数据
3. 新增【分析】和【改善方案】字段的保存和读取接口

## 二、涉及页面

1. **成品链接监控** (`/api/finished/link/monitor/list`)
2. **潜力链接监控** (`/api/potential/link/monitor/list`)
3. **自然流商品监控** (`/api/natural/stage/monitor/list`)

## 三、接口变更详情

### 3.1 列表接口返回数据变更

#### 3.1.1 需要移除的字段

以下字段**不再返回**（前端不再使用）：

- `visitorsAvg` - 日均访客数组 [30日, 15日, 7日, 3日, 1日]
- `visitorsVolatilityBaseline` - 访客数短期波动相对长期基准(60)指标
- `adCostAvg` - 日均广告花费数组 [30日, 15日, 7日, 3日, 1日]
- `adCostVolatilityBaseline` - 广告花费短期波动相对长期基准(60)指标
- `salesAvg` - 日均销售额数组 [30日, 15日, 7日, 3日, 1日]
- `salesVolatilityBaseline` - 销售额短期波动相对长期基准(60)指标

#### 3.1.2 保留的字段

以下字段**继续返回**：

- `id` - 商品ID
- `name` - 商品名称
- `image` - 商品图片
- `warningLevel` - 预警等级
- `warningMessages` - 警告信息
- `custom_category_1` ~ `custom_category_4` - 自定义分类

#### 3.1.3 新增字段

在列表接口返回数据中，**新增以下字段**：

```typescript
{
  // ... 原有字段 ...
  analysis?: string | null;        // 分析内容（可选，最多10000字）
  improvementPlan?: string | null;  // 改善方案（可选，最多10000字）
}
```

### 3.2 新增折线图数据接口

#### 3.2.1 成品链接监控折线图接口

**接口地址**: `GET /api/finished/link/monitor/chart`

**请求参数**:
- `shopID` (query, 必需): 店铺ID
- `shopName` (query, 必需): 店铺名称
- `productID` (query, 必需): 商品ID
- `startDate` (query, 必需): 开始日期，格式 YYYY-MM-DD
- `endDate` (query, 必需): 结束日期，格式 YYYY-MM-DD

**响应格式**:
```json
{
  "success": true,
  "message": "查询成功",
  "data": {
    "dates": ["2024-01-01", "2024-01-02", "2024-01-03", ...],
    "visitors": [100, 120, 95, ...],           // 访客数
    "cartRate": [0.15, 0.18, 0.12, ...],      // 加购率（小数，如0.15表示15%）
    "conversionRate": [0.05, 0.06, 0.04, ...], // 转化率（小数，如0.05表示5%）
    "orderCount": [5, 7, 4, ...],              // 订单量（ordered_items）
    "buyerCount": [4, 6, 3, ...],             // 买家数（confirmed_buyers）
    "gmv": [500.00, 700.00, 400.00, ...]      // GMV（confirmed_sales，单位：THB）
  }
}
```

**数据计算规则**:
- `visitors`: 从 `daily_product_stats` 表的 `visitors` 字段获取
- `cartRate`: 计算 `cart_visitors / visitors`，如果 `visitors` 为0则返回 `null`
- `conversionRate`: 从 `daily_product_stats` 表的 `confirmed_conversion` 字段获取（已确认转化率）
- `orderCount`: 从 `daily_product_stats` 表的 `ordered_items` 字段获取
- `buyerCount`: 从 `daily_product_stats` 表的 `confirmed_buyers` 字段获取
- `gmv`: 从 `daily_product_stats` 表的 `confirmed_sales` 字段获取

**注意事项**:
- 日期范围：按 `startDate` 和 `endDate` 查询，包含边界日期
- 数据排序：按日期升序排列
- 缺失数据：如果某天没有数据，该日期对应的数组位置应为 `null`
- 日期数组：`dates` 数组应包含查询范围内的所有日期（即使某天没有数据也要包含该日期）

## 四、数据库变更

### 4.1 表结构变更

需要在 `product_items` 表中新增两个字段：

```sql
ALTER TABLE product_items 
  ADD COLUMN analysis TEXT DEFAULT NULL COMMENT '分析内容（最多10000字）',
  ADD COLUMN improvement_plan TEXT DEFAULT NULL COMMENT '改善方案（最多10000字）';
```

**字段说明**:
- `analysis`: 分析内容，TEXT类型，可为NULL
- `improvement_plan`: 改善方案，TEXT类型，可为NULL
- 两个字段都支持最多10000字符（MySQL的TEXT类型可以存储65535字节，足够存储10000个中文字符）

### 4.2 数据查询

在列表接口中，需要查询这两个字段：

```sql
SELECT 
  product_id,
  product_name,
  product_image,
  analysis,
  improvement_plan,
  -- ... 其他字段
FROM product_items
WHERE ...
```

### 4.3 数据更新

在保存接口中，更新这两个字段：

```sql
UPDATE product_items
SET 
  analysis = ?,
  improvement_plan = ?
WHERE shop_id = ? AND product_id = ?
```

## 五、Service层变更

### 5.1 修改现有方法

需要修改以下三个方法，移除不再需要的字段计算：

1. `getFinishedLinkMonitorData()` - 移除 `visitorsAvg`、`visitorsVolatilityBaseline`、`adCostAvg`、`adCostVolatilityBaseline`、`salesAvg`、`salesVolatilityBaseline` 的计算和返回
2. `getPotentialLinkMonitorData()` - 同上
3. `getNaturalStageMonitorData()` - 同上

**注意**: 虽然不再返回这些字段，但可以考虑保留计算逻辑（注释掉），以便未来可能需要恢复。

### 5.2 新增方法

需要新增以下方法：

1. `getFinishedLinkMonitorChartData(shopID, shopName, productID, startDate, endDate)` - 获取成品链接监控折线图数据
2. `getPotentialLinkMonitorChartData(shopID, shopName, productID, startDate, endDate)` - 获取潜力链接监控折线图数据
3. `getNaturalStageMonitorChartData(shopID, shopName, productID, startDate, endDate)` - 获取自然流商品监控折线图数据
4. `saveFinishedLinkMonitorAnalysis(shopID, shopName, productID, analysis, improvementPlan)` - 保存成品链接监控分析
5. `savePotentialLinkMonitorAnalysis(shopID, shopName, productID, analysis, improvementPlan)` - 保存潜力链接监控分析
6. `saveNaturalStageMonitorAnalysis(shopID, shopName, productID, analysis, improvementPlan)` - 保存自然流商品监控分析

### 5.3 折线图数据查询SQL示例

```sql
SELECT 
  date,
  visitors,
  cart_visitors,
  confirmed_conversion,
  ordered_items,
  confirmed_buyers,
  confirmed_sales
FROM daily_product_stats
WHERE shop_id = ? 
  AND product_id = ? 
  AND date >= ? 
  AND date <= ?
ORDER BY date ASC
```

然后在代码中处理数据：
- 计算加购率：`cartRate = cart_visitors / visitors`（如果visitors为0则为null）
- 构建日期数组（包含所有日期，即使没有数据）

## 八、错误处理

### 8.1 折线图接口错误处理

- 如果 `startDate` 或 `endDate` 格式错误，返回400错误
- 如果日期范围超过合理范围（建议限制在1年内），返回400错误
- 如果商品不存在，返回404错误
- 如果查询失败，返回500错误

### 8.2 保存接口错误处理

- 如果必填参数缺失，返回400错误
- 如果 `analysis` 或 `improvementPlan` 超过10000字符，返回400错误
- 如果商品不存在，返回404错误
- 如果保存失败，返回500错误

## 九、性能优化建议

1. **折线图数据查询优化**:
   - 确保 `daily_product_stats` 表有 `(shop_id, product_id, date)` 的联合索引
   - 如果数据量很大，考虑限制查询日期范围（如最多查询365天）

2. **列表接口优化**:
   - 移除不必要的计算后，列表接口性能应该会提升
   - 确保 `product_items` 表的查询有适当的索引

## 十、测试要点

1. **列表接口测试**:
   - 验证不再返回已移除的字段
   - 验证新增的 `analysis` 和 `improvementPlan` 字段正确返回
   - 验证空值处理正确

2. **折线图接口测试**:
   - 验证日期范围查询正确
   - 验证数据计算正确（特别是加购率的计算）
   - 验证缺失数据的处理（返回null）
   - 验证日期数组包含所有日期

3. **保存接口测试**:
   - 验证必填参数校验
   - 验证字数限制（10000字符）
   - 验证保存和读取的一致性

## 十一、兼容性说明

- 本次变更**不兼容**旧版本前端
- 需要前端同步更新才能正常使用
- 建议在发布前与前端确认接口格式
