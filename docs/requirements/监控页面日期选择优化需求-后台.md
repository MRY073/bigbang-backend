# 监控页面日期选择优化需求文档（后台开发）

## 一、需求概述

对三个监控页面（成品链接监控、潜力链接监控、自然流链接监控）的接口进行优化，主要变更如下：
1. 列表接口不再要求 `date` 参数，改为使用默认逻辑查询商品列表
2. 折线图接口保持不变，继续支持日期范围查询

## 二、涉及接口

1. **成品链接监控列表接口** (`GET /api/finished/link/monitor/list`)
2. **潜力链接监控列表接口** (`GET /api/potential/link/monitor/list`)
3. **自然流商品监控列表接口** (`GET /api/natural/stage/monitor/list`)

**注意**: 折线图接口和保存分析接口**不需要变更**。

### 3.3 业务逻辑变更

#### 3.3.1 查询逻辑变更

**变更前**:
- 根据 `shopID`、`shopName` 和 `date` 查询指定日期的商品监控数据
- 只返回指定日期有数据的商品

**变更后**:
- 根据 `shopID`、`shopName` 查询商品列表
- **需要确定默认查询逻辑**，建议以下方案之一：
  1. **方案A（推荐）**: 查询最近有数据的日期（如最近7天内最后有数据的日期）的商品列表
  2. **方案B**: 查询所有商品（不限制日期），但预警信息基于最近的数据计算
  3. **方案C**: 查询今天有数据的商品列表

**推荐方案A的实现逻辑**:
```typescript
// 伪代码示例
async getFinishedLinkMonitorData(
  shopID: string,
  shopName: string,
  customCategory?: string,
): Promise<...> {
  // 1. 查找最近有数据的日期（最近7天内）
  const latestDate = await this.findLatestDateWithData(shopID, shopName, 7);
  
  // 2. 如果找不到，使用今天
  const queryDate = latestDate || this.getToday();
  
  // 3. 使用该日期查询商品列表
  return await this.queryProductsByDate(shopID, shopName, queryDate, customCategory);
}
```

#### 3.3.2 预警信息计算

**变更说明**:
- 预警信息的计算逻辑保持不变
- 仍然基于指定日期的数据计算预警等级和预警信息
- 只是查询日期从用户输入改为系统自动确定

```typescript
async getFinishedLinkMonitorData(
  shopID: string,
  shopName: string,
  customCategory?: string,
): Promise<...> {
  // 1. 查找最近有数据的日期（最近7天内）
  const latestDate = await this.findLatestDateWithData(shopID, shopName, 7);
  
  // 2. 如果找不到，使用今天

  // 3. 使用该日期查询商品列表（复用原有逻辑）

    shopID,
    shopName,
    queryDate,
    customCategory,
  );
}

// 辅助方法：查找最近有数据的日期
private async findLatestDateWithData(
  shopID: string,
  shopName: string,
  days: number = 7,
): Promise<string | null> {
  const today = new Date();
  const sql = `
    SELECT DISTINCT date
    FROM daily_product_stats
    WHERE shop_id = ? 
      AND date >= DATE_SUB(?, INTERVAL ? DAY)
      AND date <= ?
    ORDER BY date DESC
    LIMIT 1
  `;
  
  const result = await this.mysqlService.query(sql, [
    shopID,
    today,
    days,
    today,
  ]);
  
  if (result && result.length > 0) {
    return result[0].date;
  }
  
  return null;
}
```

## 八、错误处理

### 8.1 参数验证变更

**变更前**:
- 验证 `date` 参数是否存在
- 验证 `date` 参数格式是否正确
- 验证 `date` 参数是否为有效日期

**变更后**:
- **移除** `date` 参数的验证逻辑
- 保留 `shopID` 和 `shopName` 的验证

### 8.2 业务错误处理

**新增错误场景**:
- 如果找不到最近有数据的日期，使用今天作为默认值
- 如果今天也没有数据，返回空列表（而不是错误）

**错误处理示例**:
```typescript
try {
  const latestDate = await this.findLatestDateWithData(shopID, shopName, 7);
  const queryDate = latestDate || this.getToday();
  
  const data = await this.queryProductsByDate(shopID, shopName, queryDate);
  
  // 如果数据为空，返回空数组而不是错误
  return data || [];
} catch (error) {
  // 记录错误日志
  console.error('查询商品监控数据失败:', error);
  throw new Error('查询失败');
}
```

## 九、性能优化建议

### 9.1 查询优化

1. **索引优化**:
   - 确保 `daily_product_stats` 表有 `(shop_id, date)` 的联合索引
   - 确保查询最近日期的SQL能够利用索引

2. **缓存优化**（可选）:
   - 可以缓存每个店铺的最近数据日期
   - 缓存时间建议5-10分钟
   - 避免频繁查询数据库

3. **查询范围限制**:
   - 限制查找最近日期的范围（建议7天）
   - 避免查询过大的日期范围

### 9.2 代码优化

1. **复用查询逻辑**:
   - 如果三个监控接口的查询逻辑相似，可以抽取公共方法
   - 避免重复代码

2. **异步处理**:
   - 查找最近日期和查询商品列表可以并行处理（如果业务允许）
